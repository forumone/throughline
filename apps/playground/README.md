# @forumone/throughline-playground

Internal Next.js + Payload app used to develop and smoke-test Throughline core plugins. Never published to npm.

## One-time setup

```bash
cp .env.example .env
pnpm db:up              # starts Postgres in Docker on localhost:5433
pnpm --filter @forumone/throughline-playground dev
```

On first run, open <http://localhost:3000/admin> and create the initial admin user when Payload prompts.

## Scripts

- `pnpm dev` — Next.js dev server on :3000
- `pnpm build` / `pnpm start` — production build and serve
- `pnpm db:up` / `pnpm db:down` — bring Postgres up/down via `docker compose`
- `pnpm payload` — Payload CLI (e.g. `pnpm payload generate:types`, `pnpm payload generate:importmap`)

## Using your own Postgres

If you already run Postgres locally, skip `docker compose` and point `DATABASE_URI` in `.env` at your instance.

## Import map

`src/app/(payload)/admin/importMap.js` is regenerated by `pnpm payload generate:importmap` whenever you add custom Payload components or a plugin adds them. The committed file is a minimal empty map — regenerate locally before building if you change the config.

## Why this exists

Every core plugin should compose cleanly into a Payload config. The playground is where we prove that. Keep it minimal — no visual polish, no production hardening. The design system work lives in `packages/reference-ds/` (phase C3).
