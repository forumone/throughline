## Prerequisites

- Node.js >= 20.9
- pnpm >= 10
- A Postgres database (Neon / Supabase / self-hosted)
- An [Inngest](https://inngest.com) account (free tier is fine for development)
- A [Resend](https://resend.com) API key for transactional email

## First-time setup

```bash
# 1. Install deps (skip if you let the scaffolder do it)
pnpm install

# 2. Copy the env template
cp .env.example .env.local

# 3. Generate secrets (run each three times for the three secret slots)
openssl rand -base64 48

# 4. Edit .env.local and fill in:
#    - DATABASE_URI                — your Postgres connection string
#    - PAYLOAD_SECRET               — generated above
#    - APPROVAL_TOKEN_SECRET        — generated above
#    - FORMS_IP_HASH_SECRET         — generated above
#    - RESEND_API_KEY               — from Resend dashboard
#    - INNGEST_EVENT_KEY/SIGNING    — from Inngest (optional in local dev)

# 5. Start the dev server
pnpm dev

# 6. Visit http://localhost:3000/admin and create your first user.
```

## After admin signup

1. In the Payload admin, open **MCP → Payload MCP API Keys** and create one key. Pick a **User** — required; the key inherits that user's access control — tick **Enable API Key**, save, and copy the key. It is shown once, and it does not go in `.env.local`.

2. **Plug it into Claude (or your MCP client).** One endpoint carries every server's tools:

   ```
   POST /api/mcp
   Authorization: Bearer <your key>
   ```

   ```bash
   claude mcp add throughline http://localhost:3000/api/mcp \
     --header "Authorization: Bearer $THROUGHLINE_API_KEY"
   ```

3. **Replace the example `pages` collection** in `apps/web/src/payload.config.ts` with your real content model. Keep the `policy` group on collections that should require approval — that field shape is what the approvals plugin reads.

4. **Implement the user/group resolvers** in `payload.config.ts`. The scaffold ships with stub functions that return empty arrays so the app compiles; the approvals plugin won't actually work until they're real.
