# Throughline 1.0: where every 0.x export goes

The map from each 0.x import path to its 1.0 one, for [the 1.0 plan](1.0-plan.md)'s P3 consolidation.
It is the input to the import codemod (`throughline migrate-imports`), so it lists **every** public
path, and every name whose 1.0 path or name differs from the rest of its group. A name not listed
individually moves with its group, unchanged.

Drawn up 2026-10-02 from `main` at `bad0468`: the eleven packages' `exports` maps, followed through
every `export *`, and forumone-2026's imports at its pin `bb35603` (about 110 distinct names over
240 import sites, 85 of them `design-contract` in the design system's contract files).

## The two packages

`@forumone/throughline` takes core, plugin-contract, audit, approvals, publishing, components,
integrations, email and workflows. `@forumone/throughline-design-system` takes design-contract and
design-system-payload, and is published.

**Three subpaths more than the plan names.**

- `/rsc`. The plan lists `/client` alone, but `UsedOnPanel` and the three editorial views are
  server components that query Payload, and must not sit in a client barrel.
- `/cache-tags`. A site's front end imports it on the render path, and today's
  `workflows/cache-tags` exists precisely so that it pulls in nothing else.
- The design system has no root entry. Its 0.x root held only `fieldOverride` and the override
  types, which belong with the generator.

## Name clashes inside one subpath

Checked mechanically: every 0.x entry's exports, listed by the TypeScript checker, placed on their
1.0 subpath by the tables above, and tested for one name arriving from two sources. Three kinds of
hit, all expected:

- `DEFAULT_AUDIT_SLUG` in `/audit`, from core and from audit's renamed constant. Same value.
- `McpMeta` in `.`, from core and plugin-contract. One declaration survives, as above.
- The ten other plugin-contract types in `.`, which core's root already re-exports. Same
  declaration, reached twice.

`ContentField` and `validateOptions` appear in both packages, but never twice in one subpath.

Public names per subpath after the move: `.` 47, `/editorial` 80, `/publishing` 51, `/integrations`
44, `/media` 41, `/observability` 36, `/email` 35, `/client` 31, `/audit` 29, `/fields` 26, `/jobs`
25, `/approvals` 23, `/testing` 12, `/jobs/inngest` 10, `/rsc` 8, `/jobs/payload` 6, `/components` 4,
`/cache-tags` 4.

Generic names stay as they are (`Report`, `Command` and `Month` in `/editorial`, `Job` in `/jobs`,
`Reference` in `/media`). Each subpath is its own namespace, and renaming them would only lengthen
the codemod.

## Not covered here

- **`throughline()`'s own options**, and what the site's Inngest route does once the call registers
  every job. Today the route assembles its function list from `getEmailFunctions`,
  `getIntegrationRegistry`, `getIntegrationContext` and `getPublishingService`. Those four stay
  public, at `/email`, `/integrations` and `/publishing`, until the `throughline()` PR shows they
  can go.
- **Forms**, which is not in 1.0 (decision 4). Its last 0.x stays on npm.
- **reference-ds and create-throughline**, which become one package with no public import surface
  beyond the bin.

## How it lands

One pull request per step, each leaving `main` building and the playground running.

1. This map.
2. `@forumone/throughline`, from core and plugin-contract. The other seven packages repoint at it.
3. publishing, into `/publishing`, `/editorial`, `/client` and `/rsc`.
4. workflows, into `/jobs` and its owners. Before email and integrations, which import it.
5. audit, approvals, components, integrations and email.
6. `@forumone/throughline-design-system`, from design-contract and design-system-payload.
7. `throughline()`, with the registry, the accessors and the collector made internal.
8. The rest of the roadmap's P3 list: optional peers, the fixed version group, forms, the
   scaffolder, the codemod and the upgrade guide.

The codemod is written against this table and tested on forumone-2026's import sites. A name moved
here and not in the table is a bug in the table.
